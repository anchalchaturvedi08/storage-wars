PROJECT TYPE:
StorageWars is a modern online auction platform inspired by the concept of HistoryTV18 Show and real-world auction marketplaces.

The platform has three main user roles:
1. Super Admin
2. Bidder
3. Customer

The current phase is FRONTEND/UI DEVELOPMENT ONLY. Backend, database and real API integration will be implemented later.

==================================================
1. PROJECT PURPOSE
==================================================

The main purpose of this project is to provide an online platform where:
- Bidders can list their products for auction.
- Customers can browse available auction products.
- Customers can place bids on products.
- Super Admin can manage auctions, users, products and bids.
- Bids submitted by customers can go through an approval process.
- Customers can see the current/latest approved bid.
- Customers can see the starting price and auction ending time.
- Auction end date/time should be visible publicly, even without login.
- A live countdown timer should show the remaining auction time.
The platform should provide a simple, modern and premium auction experience.

==================================================
2. MAIN USER ROLES
==================================================

There are three main roles in the system:
A. SUPER ADMIN
B. BIDDER
C. CUSTOMER

==================================================
3. SUPER ADMIN
==================================================

Super Admin controls and manages the entire auction platform.
Admin dashboard should contain:
- Dashboard
- Auction Listings
- Bid Approvals
- Users
- Products
- Categories
- Discounts
- Reports
- Other required management options

Admin should be able to:
- View all auction listings.
- View products submitted by bidders.
- Manage users.
- View customer bids.
- Approve bids.
- Reject/block bids when required.
- Unblock an individual bid.
- Manage auction listings.
- Manage categories.
- Manage discounts.
- View platform statistics and reports.

For the current frontend-only phase, these actions can work using local/static/demo state instead of a real backend.

==================================================
4. BIDDER
==================================================

A Bidder is a user who wants to put their own product up for auction.
After login, the Bidder should get a separate Bidder Dashboard.
Bidder dashboard should contain:
- Dashboard
- Add Product
- My Products
- My Auctions
- Bids Received
- Auction Results

Bidder should be able to add a product with details such as:
- Product name
- Product image
- Product description
- Category
- Starting bid price
- Auction start date
- Auction end date
- Other relevant product details

The bidder should be able to see the products/auctions they have created.
The bidder should also be able to see bids received on their auction products.
The frontend should simulate these actions for now because backend/database is not implemented yet.

==================================================
5. CUSTOMER
==================================================

A Customer is the user who visits the website to discover auction products and place bids.
Customer can:
- Browse products.
- Search products.
- View categories.
- View auction details.
- See starting bid price.
- See current/latest approved bid.
- See auction end date.
- See countdown timer.
- Submit a bid amount.
- View their previous bids.
- View watchlist.
- View won auctions.
- View orders.
- View notifications.
The customer should be able to submit a bid amount from the auction/product detail page.
The current/latest approved bid should be clearly visible.
The auction end date and countdown timer should be visible even if the customer is not logged in.
Login should only be required when the customer actually wants to perform a protected action such as placing a bid.

==================================================
6. REAL-WORLD AUCTION FLOW
==================================================

The intended flow is:
Bidder
   ↓
Creates product
   ↓
Adds starting price
   ↓
Sets auction start date/time
   ↓
Sets auction end date/time
   ↓
Product becomes an auction listing
   ↓
Customer views product
   ↓
Customer sees starting price/current bid/end timer
   ↓
Customer submits bid
   ↓
Bid goes for approval
   ↓
Super Admin approves/rejects/manages bid
   ↓
Approved bid becomes visible as the latest/current bid
   ↓
Other customers can place higher bids
   ↓
Auction ends at specified end time
   ↓
Final/winning bid can be determined
